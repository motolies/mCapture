# mCapture 시스템 모니터(CPU·메모리) 구현 계획

## Context

- **목적**: 메뉴바에 CPU·메모리 사용량 항목(두 줄 `CPU / 24%`, `MEM / 60%`)을 추가하고, 누르면 iStat Menus식 상세 팝오버(CPU 기록 막대·코어 링·프로세스·GPU·로드·가동 시간 / 메모리 압력·사용 링·내역·프로세스·페이지 입출력·스왑)를 띄운다.
- **설정**: 설정 창에 **시스템 모니터** 탭을 추가해 항목별 표시 여부와 임계값을 둔다. 임계값을 넘으면 그 메뉴바 항목의 글자를 빨간색으로 그린다.
- **확정된 결정 (사용자 답변)**
  - 메모리 지표는 **압력**(`100 − kern.memorystatus_level`). 메뉴바 MEM 값과 임계값 모두 압력 기준. 팝오버에는 압력·사용률 링을 둘 다 보인다.
  - **GPU 포함**(IORegistry `IOAccelerator` → `PerformanceStatistics`, 이 Mac에서 `Device Utilization %`·`In use system memory` 확인). **온도는 마지막 단계**에서 SMC로 시도하고 안 읽히면 숨긴다. FPS·GHz는 공개 API가 없어 뺀다.
  - 프로세스 목록은 **혼합**: CPU 목록은 `ps -Aro pid=,pcpu=,comm=`(전 프로세스, 20ms), 메모리 목록은 `proc_listpids` + `proc_pid_rusage`의 `ri_phys_footprint`(내 계정 프로세스만, 활성 상태 보기와 같은 값). 팝오버가 열려 있는 동안만 조회.
- **이 Mac에서 확인한 사실 (2026-10-21)**: M4 Pro 14코어(`hw.perflevel1`=효율 4, `hw.perflevel0`=성능 10, 효율 코어가 앞 번호), 24GB, 페이지 16KB. `proc_pid_rusage`·`proc_pidinfo`는 다른 사용자 프로세스(kernel_task·WindowServer·root)에서 EPERM. `ps`는 `com.apple.system-task-ports.read` 엔타이틀먼트로 전부 읽는다. `top -l 1`은 0.5초라 주기 조회에 부적합. SF Symbol `gauge.with.dots.needle.bottom.50percent`·`cpu`·`memorychip` 사용 가능. 메뉴바 두께 22pt.

## 설계

### 고정값

| 항목 | 값 |
|---|---|
| 갱신 주기 | 2초 (상수, 설정 없음) |
| CPU 기록 | 60샘플(2분), 사용자·시스템 분리 |
| 메뉴바 항목 | `NSStatusItem` 2개(CPU, MEM), `autosaveName`으로 사용자 배치 기억. 생성 순서: 기존 아이콘 → MEM → CPU (왼쪽부터 CPU, MEM, 아이콘) |
| 메뉴바 글자 | 직접 그린 `NSImage`(폭 고정 약 34pt, 높이 22pt, 위 "CPU" 8pt medium, 아래 "24%" 11pt semibold monospacedDigit). 평소 `isTemplate = true`(밝은·어두운 메뉴바 자동), 임계값 초과 시 `systemRed` 비템플릿 — 잠자기 방지 아이콘과 같은 규칙(`StatusItemController.updateAppearance`) |
| 팝오버 | `NSPopover` + `NSHostingController`, `behavior = .transient`, 폭 300pt. 비활성(LSUIElement) 앱에서 바깥 클릭에 닫히도록 `NSEvent.addGlobalMonitorForEvents(.leftMouseDown/.rightMouseDown)`로 보조. 다른 항목을 누르면 열린 팝오버를 먼저 닫음. 열린 동안 버튼 `isHighlighted` |
| 색 | 사용자/성능 코어/앱 = `.blue`, 시스템/효율 코어/와이어드 = `.pink`, 압축됨 = `.yellow`, 여유 = `.gray`. 압력 링은 `kern.memorystatus_vm_pressure_level`(1 보통 초록·2 경고 노랑·4 위험 빨강) |
| 임계값 기본 | CPU 80%, 메모리 압력 70%. 둘 다 "알림 사용" 토글 기본 켜짐 |
| 표시 기본 | CPU·MEM 모두 켜짐 (개인용 앱) |

### 앱 연동

- `AppDelegate`: `private lazy var systemMonitor = SystemMonitorController(preferences:)`, `applicationDidFinishLaunching`에서 `statusItem` 생성 **뒤** `systemMonitor.start()`.
- `SettingsTab`에 `case monitor` 추가 → `SettingsWindowController.content(for:)`에 분기, 툴바·URL은 `allCases`로 자동.
- DEBUG URL (`AppDelegate.handle`):
  - `debug/monitor-stats?path=/abs/out.json`: 설정을 다시 읽은 뒤 최신 스냅샷·기록 길이·프로세스 상위 5(두 목록)·GPU·온도 여부를 JSON으로
  - `debug/monitor-show?kind=cpu|memory[&path=/abs/out.png]`: 팝오버를 열고(이미 열렸으면 닫기), `path`가 있으면 0.5초 뒤 팝오버 내용 뷰 레이어를 PNG로(`DebugSnapshot.write`의 렌더링 부분을 `render(view:to:)`로 뽑아 재사용. SwiftUI 호스팅 뷰라 위아래 뒤집힘 → `sips -f vertical`)
- `Log`에 `monitor` 카테고리 추가.

## 단계 (각 단계 = 커밋 하나, `swift build`·`./scripts/test.sh` 통과, 커밋 메시지 한국어 `feat:`)

0. **준비**: `git worktree list`로 다른 세션 확인(있으면 `.claude/worktrees/`에서 작업). 이 계획을 `claudedocs/시스템-모니터-구현-계획.md`로 저장.
1. **Core 계산·형식**: `CPULoad`, `MemoryUsage`, `UsageHistory`, `ProcessUsage`, `MonitorFormat` + `Tests/MCaptureCoreTests/SystemMonitorTests.swift`
   - 틱 차이 → % (idle만 늘면 0, 전부 busy면 100, 코어별·효율/성능 평균, 첫 샘플은 nil)
   - 메모리 내역 합 = 총량, 압력 = 100 − level, 페이지 입출력 차이·초당
   - `ps` 파서: 공백 있는 경로, `kernel_task`(경로 없음), 잘못된 줄 무시, 상위 N
   - 표시 이름: `/Applications/Warp.app/Contents/MacOS/stable` → `Warp`, `/usr/sbin/bluetoothd` → `bluetoothd`
   - 형식: `5.5GB`·`812MB`·`0KB`, `4일 20시간`·`20시간 5분`·`12분`
2. **읽기·샘플러·메뉴바 항목**: `SystemStatsReader`, `SystemMonitor`, `MonitorStatusItem`(팝오버 없이 글자만), `SystemMonitorController`, `Preferences` 키, `AppDelegate` 연결, `debug/monitor-stats`. 임계값 색까지.
3. **설정 탭**: `SettingsTab.monitor`, `SystemMonitorSettingsView`, KVO 반영, `settings?tab=monitor`.
4. **팝오버 UI**: `MonitorWidgets`, `CPUDetailView`(온도·GPU 자리 포함, 값 없으면 숨김), `MemoryDetailView`, `ProcessStatsReader`, 팝오버 토글·닫힘, `debug/monitor-show`.
5. **GPU**: `SystemStatsReader`에 IORegistry 읽기, CPU 팝오버 GPU 카드.
6. **온도 (best effort)**: `SMCTemperature`. 이 Mac에서 키 목록을 덤프해 CPU 온도 키를 확인한 뒤 패턴 확정. 못 읽으면 숨김 유지.
7. **문서** (같은 커밋 또는 마지막 커밋): `claudedocs/mcapture-개발-스펙.md`(F29 "5단계: 시스템 모니터", 설정 표, URL 표, 디렉터리 구조·아키텍처 다이어그램, 테스트 표, UI 확인·수동 확인 목록, 결정 기록 — 압력 선택·혼합 프로세스·2초·ps 사용·다른 사용자 프로세스 제약·SMC), `claudedocs/USAGE.md`("8. 시스템 모니터" 절, 설정 절·URL 표 갱신), `README.md` 기능 목록.

## 검증

- **단위 테스트**: 1단계 테스트 약 25개, `./scripts/test.sh`.
- **dev 앱 실제 조작** (메모리 규칙: dev 앱만, 창을 앞으로 가져오지 않음, 끝나면 `pkill -x mCaptureDev`, `defaults read com.motolies.mcapture`가 그대로인지 확인)
  1. `./scripts/build-app.sh && open build/mCapture-dev.app`
  2. 메뉴바 항목 확인: `osascript` `tell process "mCaptureDev"` → `menu bar 2`의 항목 수가 3(CPU·MEM·아이콘)인지, 이름(`accessibility description`)에 값이 들어 있는지
  3. `open "mcapture-dev://debug/monitor-stats?path=…json"` → CPU 전체·코어 14개(효율 4)·메모리 내역 합 ≈ 24GB·압력 = 100 − `sysctl kern.memorystatus_level`·스왑이 `sysctl vm.swapusage`와 같은지·로드 평균이 `sysctl vm.loadavg`와 같은지·GPU 값이 `ioreg -r -c IOAccelerator`와 비슷한지 비교
  4. 임계값: `defaults write com.motolies.mcapture.dev monitorCPUThreshold -int 1` → 2초 뒤 메뉴바 CPU 글자가 빨간색(`debug/monitor-stats`의 `alert` 플래그와 `menu bar 2` 스크린샷은 화면 기록 권한이 없으므로 플래그·로그로 확인). 되돌린 뒤 `monitorCPUVisible -bool false` → 항목 수 2
  5. `debug/monitor-show?kind=cpu&path=…png` / `kind=memory` → `sips -f vertical` 뒤 PNG 확인(막대·링·프로세스·GPU·로드·가동 시간 / 압력·사용 링·내역·프로세스·페이지·스왑). 프로세스 목록이 `ps -Aro` 상위와 `top -l 1 -o mem` 상위(내 계정)와 일치하는지
  6. 팝오버가 열린 동안 CPU 비용: `ps -o %cpu -p $(pgrep -x mCaptureDev)`가 평소 ≈ 0%, 팝오버 열림 ≈ 1~2% 이하
  7. 설정 창: `settings?tab=monitor`로 열어 `debug/snapshot` PNG로 탭 내용 확인 (앞으로 가져오지 않음, 텍스트 필드 없음)
  8. 끝: 시험용 dev 키 삭제(`defaults delete com.motolies.mcapture.dev monitorCPUThreshold` 등), `pkill -x mCaptureDev`
- **수동 확인 (스펙 11절에 추가)**: 밝은·어두운 메뉴바에서 글자, 임계값 초과 빨간색, 다른 앱 활성 상태에서 팝오버 열고 바깥 클릭으로 닫힘, 3개 디스플레이 각각의 메뉴바에서 팝오버 위치, 전체 화면 앱 위, ⌘-드래그로 항목 위치 바꾼 뒤 재실행에도 유지, 설정 토글 즉시 반영, 하루 사용 후 메모리·CPU 누수 없음(`footprint -p`).

## 주요 위험

| 위험 | 완화 |
|---|---|
| 비활성 앱의 `.transient` 팝오버가 바깥 클릭에 안 닫힘 | 전역 마우스 모니터로 닫기. 그래도 안 되면 `NSMenu` + 커스텀 뷰로 전환(단, 메뉴 추적 중엔 메인 큐가 멈추므로 `Timer`로 갱신) |
| SMC 키가 M4 Pro에서 다름 | 키 전부 열거해 패턴으로 고르고, 없으면 숨김. 6단계로 분리해 실패해도 나머지 영향 없음 |
| `ps` 서브프로세스 비용·파싱 | 팝오버 열린 동안만 2초마다 1회(20ms). 경로는 마지막 열로 받아 공백 안전 |
| 메모리 목록에 WindowServer 등이 빠짐 | 설정 캡션과 스펙에 제약 기록 (공개 API 한계) |
| 메뉴바 글자 폭이 값마다 흔들림 | 폭 고정 + monospacedDigit |
| `UserDefaults` KVO가 외부 변경에 안 올 수 있음 | `debug/monitor-stats`가 먼저 설정을 다시 읽음 |
