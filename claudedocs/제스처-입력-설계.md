# 제스처 입력 설계 (MCaptureCore/Gesture · Multitouch)

매직마우스 2·3·4손가락 제스처를 BTT처럼 동작에 매핑하기 위한 입력 계층의 설계다. 2026-10-22 PoC(`매직마우스-제스처-poc.md`)로 비공개 `MultitouchSupport.framework`의 접촉 프레임이 권한 없이 들어오고 탭·스와이프·클릭이 구분됨을 확인한 뒤, 인식 로직을 `MCaptureCore`로 옮기고 다른 입력 장치를 붙일 수 있는 모양으로 정리했다(F30). 앱의 트리거→액션 설정(F31)은 이 위에 올린다.

## 레이어

```
앱 (F31, 예정)   GestureService(@MainActor): for await event in source.events → GestureBinding[spec → action] → 액션 실행
──────────────────────────────────────────────────────────────────────────────────────────
MCaptureCore/Gesture  (순수 로직, Foundation만, 단위 테스트 대상)
  모델       TouchContact·TouchFrame / InputDeviceKind·SurfaceSize·InputDeviceDescriptor / MouseButton
             InputGesture(종류·손가락·방향·버튼) · GestureMetrics · GestureEvent(장치가 붙은 이벤트)
  인식기     TouchGestureRecognizer: 값 타입 상태 기계 + Profile(장치별 임계값·필터)      ← 터치 장치 확장 지점
  파이프라인 GesturePipeline: 장치별 인식기 · 직렬 큐 · 끊김 정리 · 클릭 중복 제거 · Observer(동기)
  소스 계약  InputSource: devices · events(AsyncStream) · start/stop                    ← 비터치 장치 확장 지점
  트리거     GestureSpec: 조건 문자열(mouse+3+swipe+left) ↔ 값, matches(event)
  로그 형식  TouchFrameLog: --raw 한 줄 쓰기·읽기 (CLI 기록·재생, 테스트 픽스처)
──────────────────────────────────────────────────────────────────────────────────────────
MCaptureCore/Multitouch  (macOS 어댑터, 비공개 프레임워크, Gesture/의 공개 API만 사용, 테스트 없음)
  MultitouchAPI(dlopen·dlsym, load() throws) · MultitouchDevice(+IORegistry 열거) · MultitouchCallbackRouter(전역 C 콜백)
  MultitouchInputSource: InputSource 구현 (장치 시작/정지, 프레임 → 파이프라인, AsyncStream)
──────────────────────────────────────────────────────────────────────────────────────────
gesturelab (CLI, 앱 번들 밖): 옵션 · 장치 표 · raw/이벤트 출력(Observer) · CGEventTap 보조 클릭 · 재생 · SIGINT
```

`Multitouch/`를 코어에 둔 이유: 진단 CLI가 앱 타깃에 의존할 수 없다. `Gesture/`의 공개 API만 쓰므로 나중에 라이브러리 타깃으로 폴더째 떼어낼 수 있다.

## 데이터 흐름과 스레드

```
MultitouchSupport 스레드 ─▶ MultitouchCallbackRouter.frameCallback (잠금 보호 표에서 핸들러를 찾아 잠금 밖에서 호출)
                         ─▶ GesturePipeline.ingest  →  직렬 큐  →  TouchGestureRecognizer.process
                                                               →  Observer.frame/event (동기, CLI)
                                                               →  AsyncStream.yield (앱, 최신 16개 버퍼)
MT 버튼 콜백 ─▶ router.buttonCallback ─▶ pipeline.buttonChanged(device:)  ─┐ 같은 클릭을 둘 다 알려 주므로
CGEventTap(CLI만) ─▶ pipeline.buttonChanged (최근 프레임 장치로)            ─┘ 인식기가 150ms 안 두 번째를 버린다
```

- 콜백은 컨텍스트 없는 C 함수 포인터만 받고(`MTRegisterButtonStateCallback`에는 refcon 변종이 없다) 등록·해제에 같은 포인터가 필요하므로, 콜백은 `static let` 하나씩이고 장치 포인터 비트 → 핸들러 표(`OSAllocatedUnfairLock`)로 라우팅한다. 핸들러는 소스가 아니라 파이프라인을 잡는다. 소스가 멈추는 중에 들어온 콜백도 살아 있는 큐에 떨어진다.
- 파이프라인의 가변 상태는 모두 큐 안에서만 만진다(`@unchecked Sendable`, `FileEventWatcher`와 같은 구조). 인식기는 사전 안에서 제자리 변경한다(복사 후 재대입하면 추적 사전이 프레임마다 복사된다).
- 버튼 시각은 벽시계가 아니라 **마지막 프레임의 장치 시각**이다. 두 클릭 경로의 중복 제거가 같은 시계를 전제한다.
- 정지 순서: 콜백 해제 → `MTDeviceStop` → 라우터 정리 → `pipeline.drain()`(큐 배수) → `continuation.finish()`. 콜백 안(프레임워크 스레드)에서 `stop()`을 부르면 안 된다. 한 번 멈춘 소스는 다시 시작하지 않고 새로 만든다.

## 핵심 타입

| 파일 | 타입 | 역할 |
|---|---|---|
| `Gesture/InputDevice.swift` | `InputDeviceKind` | 장치 종류. rawValue(`mouse`·`trackpad`·`builtin`·`unknown`)는 트리거 문자열에 들어가므로 고정 |
| | `DeviceFamily.kind(forFamilyID:)` | MultitouchSupport Family ID → 종류 (112 마우스, 128~130 매직트랙패드, 98~111·113 내장) |
| | `InputDeviceDescriptor` | `id`(IORegistry Multitouch ID, 재연결에도 같음)·종류·이름·표면 mm |
| `Gesture/TouchFrame.swift` | `TouchPhase`·`TouchContact`·`TouchFrame` | 접촉 상태(0~7)·접촉 하나·프레임 하나. 센서가 보는 접촉 전부가 프레임에 들어 있다 |
| `Gesture/InputGesture.swift` | `GestureKind` | tap·longPress·click·swipe + 진단용 move·hold(`isAssignable == false`) |
| | `SwipeDirection` | left·right·up·down. +y가 손끝 쪽. 표시는 장치에 따라 앞·뒤 / 위·아래 |
| | `InputGesture` | 종류·손가락·방향·버튼. 트리거 조건과 비교하는 단위. SwiftUI `Gesture`와 겹쳐 이 이름 |
| | `GestureEvent` | 장치 + 제스처 + 측정값(mm·초) + 장치 시각. `description`은 CLI 출력 형식 |
| `Gesture/TouchGestureRecognizer.swift` | `TouchGestureRecognizer` | "거의 동시에 닿은 손가락 묶음"을 제스처로 보는 상태 기계. 프레임에 없는 경로 = 떨어짐 |
| | `.Thresholds`·`.Profile` | 임계값과 장치별 설정. `Profile.default(for:surface:)`가 종류별 기본값(지금은 매직마우스만) |
| `Gesture/GesturePipeline.swift` | `GesturePipeline` | 장치별 인식기를 직렬 큐에서 돌리고 `Observer`로 알린다. `addDevice`/`removeDevice`(재연결용) |
| `Gesture/InputSource.swift` | `InputSource` | 소스 계약. 앱은 이것만 본다 |
| `Gesture/GestureSpec.swift` | `GestureSpec` | 트리거 조건. `HotKeySpec`처럼 `init?(string:)`·`stringValue`·`displayName`, `matches(_:)` |
| `Gesture/TouchFrameLog.swift` | `TouchFrameLog` | raw 로그 줄 형식. 쓰기와 읽기가 한곳에 있어 어긋나지 않는다 |
| `Multitouch/MultitouchAPI.swift` | `MultitouchAPI`·`MultitouchError` | dlopen/dlsym. 정적 초기화 없이 `load()`로만 연다 |
| `Multitouch/MultitouchDevice.swift` | `MultitouchDevice`·`MultitouchDeviceEnumerator` | 장치(포인터는 비트로 보관)와 열거(CreateList + IORegistry 보강, 진단 메모 반환) |
| `Multitouch/MultitouchCallbackRouter.swift` | `MultitouchCallbackRouter` | 전역 C 콜백 → 장치별 핸들러 |
| `Multitouch/MultitouchInputSource.swift` | `MultitouchInputSource` | `InputSource` 구현. 프로필이 없는 종류의 장치는 건너뛴다 |

## 디자인 패턴과 확장 지점

| 패턴 | 적용 | 무엇이 바뀌면 어디를 고치나 |
|---|---|---|
| Strategy(데이터로) | `TouchGestureRecognizer.Profile` | 터치 장치의 임계값·필터 차이. 상태 기계(도착 묶음·프레임 부재=떨어짐)는 장치 중립이며 트랙패드에서 먼저 검증됐다. 다른 상태 기계가 필요해지면 그때 프로토콜을 뽑는다(파이프라인은 `process`·`buttonDown`·`flush`·`filter` 네 가지만 쓴다) |
| Adapter | `MultitouchInputSource` | 비공개 프레임워크의 C 콜백·포인터를 `InputSource`로 감싼다 |
| Observer | `GesturePipeline.Observer`(동기) / `InputSource.events`(AsyncStream) | CLI는 전자(프레임 줄과 이벤트 줄의 순서 보존), 앱은 후자 |
| Specification | `GestureSpec.matches(_:)` | 트리거 조건. 장치 종류(nil=모두)와 제스처 동일성 |
| Command(다음 단계) | `GestureBinding(spec, action)` + 앱 액션 | 설정 UI 단계 |

### 터치 장치 추가 (예: 매직트랙패드)

1. `DeviceFamily.kind(forFamilyID:)`에 Family ID가 이미 매핑돼 있는지 확인한다(128~130은 `.magicTrackpad`).
2. `TouchGestureRecognizer.Profile.default(for:surface:)`의 `switch`에 case를 더한다. 트랙패드는 손가락을 얹어 두지 않으므로 `filterResting = false`, 가장자리 호버 보정 `edgeHoverX = 0`, 표면이 커서 `swipeMinMM`을 키우는 식이다. 실측 전에는 추정값임을 주석에 적는다.
3. `swift run gesturelab --all --raw`로 기록하고 `--replay`로 임계값을 맞춘 뒤, 조각을 `Tests/MCaptureCoreTests/GestureFixtures.swift`에 붙여 테스트를 만든다(픽스처는 raw 줄을 그대로 복사, 헤더·장치명 제외).
4. 끝. `MultitouchInputSource`는 프로필이 생긴 장치를 자동으로 시작한다. 표시 이름은 `SwipeDirection.displayName(for:)`가 종류별로 처리한다.

### 비터치 장치 추가 (예: 일반 마우스의 측면 버튼, 키보드 코드)

1. `InputSource`를 구현하는 클래스를 만든다. `devices`에 `InputDeviceDescriptor`(종류는 필요하면 `InputDeviceKind`에 case 추가), `events`는 `AsyncStream.makeStream(bufferingPolicy: .bufferingNewest(16))`.
2. 장치 이벤트를 `InputGesture`로 바꿔 `GestureEvent`로 `yield`한다. 손가락 수가 없는 장치는 `fingers: 1`로 둔다.
3. 앱의 서비스가 소스 여러 개를 쓰게 되면 그때 합성(`for await` 둘 또는 `merge`)을 서비스에 둔다. 지금은 소스가 하나라 합성 계층을 두지 않았다.

## 트리거 조건 문자열

`장치+손가락+종류[+방향|+버튼]`, 토큰 순서 고정, 소문자.

| 예 | 뜻 |
|---|---|
| `mouse+3+swipe+left` | 매직마우스 3손가락 왼쪽 스와이프 |
| `any+2+tap` | 모든 장치 2손가락 탭 |
| `mouse+4+click` / `mouse+4+click+right` | 4손가락 왼쪽 클릭(왼쪽은 생략) / 오른쪽 클릭 |
| `trackpad+3+longpress` | 매직트랙패드 3손가락 길게 탭 |

`GestureSpec(string:)`은 진단용 종류(move·hold), 방향 없는 스와이프, 종류에 안 맞는 속성을 거부한다. `HotKeySpec`처럼 Codable이 아니라 문자열로 저장하므로 `defaults write`로 넣어 볼 수 있다.

## 다음 단계: 앱 통합 (F31)

- **GestureService(@MainActor)**: 앱 시작 때 `MultitouchAPI.load()` → 열거 → `MultitouchInputSource` 생성·시작, `Task { for await event in source.events { dispatch(event) } }`. 로드 실패나 장치 없음은 조용히 비활성(설정 탭에 상태 표시).
- **블루투스 재연결**: 마우스는 유휴 약 2분이면 끊긴다. `IOServiceAddMatchingNotification`(`kIOFirstMatchNotification`/`kIOTerminatedNotification`, `AppleMultitouchDevice`)으로 알림을 받아 소스를 멈추고 다시 열거해 새로 만든다. `MTDeviceRef`는 재사용하지 않는다(`MTDeviceRelease`는 쓰지 않으므로 재연결마다 참조 하나가 남지만 유한하다). 잠자기 복귀도 같은 경로.
- **GestureBinding 저장**: `struct GestureBinding { id, spec: GestureSpec, action, isEnabled }`를 `Preferences`에 `[String]`(예: `"mouse+3+swipe+left=captureArea"`)로 둔다. 기존 `HotKeySpec`이 문자열 하나인 것과 같은 결.
- **액션**: 지금 앱 액션은 `HotKeyCenter.Action`, `StatusItemController.Actions`(클로저 묶음), `AppDelegate`의 `@objc` 메서드, URL 라우트 네 곳에 흩어져 있다. 제스처가 다섯 번째 호출자가 되기 전에 공용 액션 enum(`AppAction`: 영역·전체·창 캡처, 텍스트 인식, 컬러 피커, 파일 찾기, 설정, 잠자기 방지 토글 …)으로 모으고 `HotKeyCenter`와 메뉴가 그것을 쓰게 하는 선행 작업이 필요하다. 그러면 트리거 UI는 "조건 → AppAction" 한 줄이다.
- **설정 탭**: `SettingsTab`에 case 하나와 `SettingsWindowController.content(for:)` 분기. 화면은 바인딩 목록(조건 표시 이름 · 액션 · 켬/끔)과 "제스처 녹음" 버튼(소스의 다음 `isAssignable` 이벤트를 조건으로 채움). `GestureKind.allCases.filter(\.isAssignable)`로 종류 목록을 만든다.
- **기본 매핑 권고**: OS가 이미 쓰는 1손가락 스크롤·2손가락 좌우(페이지 넘기기)·더블탭(스마트 줌)과 겹치지 않게 3·4손가락 위주로. 제스처 억제는 불가능하고 관찰만 가능하다.
- **다중 로그인 세션**: 세션이 비활성이면 프레임이 끊긴다는 보고(MiddleClick). 비활성 알림에서 소스를 멈추고 활성에서 다시 만든다.
- **권한**: 접촉 프레임·MT 버튼 콜백은 권한이 필요 없다. 다른 앱에 키를 보내는 액션에만 손쉬운 사용이 필요하다. CGEventTap 보조 클릭 경로는 CLI 전용이며 앱에는 넣지 않는다.

## 진단 도구

```bash
swift run gesturelab                 # 매직마우스만, 제스처 이벤트 출력
swift run gesturelab --raw           # 프레임마다 접촉 좌표·state (걸러진 접촉은 x). 기록을 남겨 두면 재생할 수 있다
swift run gesturelab --all           # 모든 멀티터치 장치 (라벨 [마우스]·[장치 이름])
swift run gesturelab --replay 기록.log   # --raw 기록을 인식기에 다시 흘려 넣는다 (장치 불필요, 임계값 플래그 적용)
swift run gesturelab --help          # --tap-mm --tap-time --swipe-mm --group-ms --hold-s --edge-x --no-click --no-mt-button 등
```

인식기를 고칠 때는 고치기 전 바이너리로 `--replay` 출력을 저장해 두고(골든) 고친 뒤 같은 로그를 재생해 비교한다. 이번 이관은 두 로그(5분 기록 112·83 이벤트)에서 출력이 바이트 단위로 같았다.
