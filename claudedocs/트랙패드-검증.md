# 트랙패드 지원 검증

검증일: 2026-11-02. 개발 앱 기준. 후속 UI 개선과 함께 0.6.2에 포함한다.

## 자동 검증

- `./scripts/test.sh`: 320개 테스트. 기존 마우스 회귀, 내장·외장 초기 프로필, 2~4손가락 탭·길게 탭·네 방향 쓸기·좌우 클릭, 클릭 뒤 중복 탭 방지, 잘못된 표면 크기 거부, 장치별 이벤트와 버튼 시계 분리, 공통 설정 우선순위, 저장 문자열 왕복을 포함한다.
- `./scripts/build-app.sh debug`: 개발 앱 조립·서명.
- 실제 입력은 `Tests/MCaptureCoreTests/GestureFixtures.swift`의 `TrackpadLiveFixtures`에 보관하고 `TrackpadLiveTests`로 재생한다.

## 실기기 입력

| 장치 | 표면 크기 | 확인한 입력 |
|---|---|---|
| 내장 트랙패드 (Family 111) | 156 × 96mm | 3손가락 탭, 왼쪽·오른쪽 쓸기 각 1회 |
| Magic Mouse (Family 112) | 51.52 × 90.56mm | 3손가락 탭, 왼쪽·오른쪽 쓸기 각 2회 |
| 외장 Magic Trackpad | 미연결 | 합성 테스트만 수행 |

사용자가 직접 입력한 프레임을 장치별로 분리해 각각의 기본 프로필로 재생했다. 진단 수집 시 공통으로 적용한 트랙패드 10mm 기준에서는 마우스의 첫 왼쪽 쓸기가 이동으로 분류됐지만, 기존 마우스 6mm 프로필로 재생하면 정상 인식된다. 마우스 기본값은 변경하지 않았다.

두 장치의 내부 시각이 다른 사실도 확인했다. 파이프라인의 버튼 판정과 이벤트 시각을 장치별로 분리했고, 서로 다른 시계를 교차 입력하는 테스트를 추가했다. 과거 수집 기록의 상대 시각은 그대로 보존했다.

## UI 점검

개발 앱의 AppKit 시트와 접근성 요소, 디버그 서비스 상태를 확인했다.

- 미연결 외장 트랙패드 선택 시 직접 입력만 비활성화되고 수동 등록·저장이 가능하다.
- 신규 설정은 제스처와 동작을 지정하기 전에는 저장할 수 없다.
- 편집 시 기존 값을 불러오고, 취소하면 기존 설정이 유지된다. 수정 저장 시 꺼짐 상태가 유지된다.
- 내장 트랙패드 입력 대기 중 마우스 합성 이벤트는 무시하고, 내장 이벤트를 받으면 입력을 종료한다.
- 모든 장치 입력은 감지 장치로 범위를 바꾸지 않는다.
- 키 입력 시작·종료 시 키 입력용 중지는 전환되지만 편집용 중지는 유지된다.
- 삭제 확인 시 대상 제스처·동작 요약을 표시한다. UI 점검용 설정은 모두 삭제했다.
- 설정창 종료 후 `settingsVisible`, `recording`, `editingPaused`, `keyRecordingPaused`가 모두 false이고 등록 목록은 비어 있음을 확인했다.
- 펼친 수동 입력은 스크롤되며 저장·취소는 스크롤 영역 밖에 유지된다.

## 남은 실환경 점검

- 외장 Magic Trackpad 실제 입력·재연결·잠자기 복귀.
- 내장 트랙패드 2·4손가락 및 길게 탭·물리 클릭 전체 조합의 실측. 현재는 합성 테스트로 검증했다.
- 실제 작은 화면, VoiceOver 읽기 순서와 전체 키보드 탐색.
- 다른 앱 전환 시 입력 종료의 실제 포커스 전환 검증. 자동화 환경에서 메뉴바 앱 활성화 상태를 안정적으로 만들지 못했으며, 앱 비활성 알림과 NSWorkspace 앱 전환 알림을 함께 처리한다.
- 중복 오류의 UI 표시 및 시트 포커스 전환 전체 시나리오 수동 확인. 중복 저장 방지와 장치 범위 우선순위는 코드 및 코어 테스트로 확인했다.
