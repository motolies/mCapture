# mCapture "파일 찾기" 구현 계획 (feature/find-file)

## Context

- **목적**: Windows Everything이나 macOS Cling처럼 **파일·폴더 이름으로 즉시 찾는 기능**을 mCapture에 넣습니다.
- **배경**: Cling은 유료(Pro €15)이고 무료 모드에는 제한이 있습니다. 그래서 상주 중인 mCapture에 직접 넣기로 했습니다.
- **결과물**: 전역 단축키로 뜨는 Spotlight식 패널입니다. 글자를 칠 때마다 결과를 보여 주고, 열기, Finder에서 보기, 경로 복사를 할 수 있습니다.
- **현재 상태**: 브랜치 `feature/find-file`(master 38f9a3d에서 갈라짐)가 만들어져 있고 커밋은 아직 없습니다.

## 확정된 결정

| 항목 | 결정 |
|---|---|
| 검색 대상 | 파일·폴더 **이름**만 (내용 검색 없음) |
| 루트 | `~`, `/Applications`, `/System/Applications` (설정에서 추가·삭제) |
| 인덱스 | 자체 메모리 인덱스 + FSEvents 증분 갱신 + 디스크 스냅샷 |
| 기본 제외 (폴더 자체는 검색되고 안은 색인 안 함) | 이름: `node_modules`, `.git`, `.svn`, `.hg`, `DerivedData`, `__pycache__`, `.build`<br>경로: `~/.Trash`, `~/Library/Caches`, `~/Library/Logs`, `~/Library/Containers`, `~/Library/Group Containers`, `~/Library/CloudStorage`<br>패키지(.app 등)는 내부만 제외 |
| ~/Library | 색인함. 보호 폴더(Mail 등)의 EPERM은 조용히 건너뜀 |
| 숨김(점으로 시작하는 이름) | 기본 끔 |
| 예상 규모 | 약 110만 항목 (실측: ~ 145만, ~/Library 57만, node_modules 22.5만) |
| 매칭 | 퍼지(fzf식), 필터(`ext:`, `folder:`, `file:`, `/` 포함 경로항, 공백 = AND), 한글 초성, `regex:` |
| 랭킹 | 정확 > 접두 > 경계 > 부분 > 퍼지. `.app`에 보너스 |
| 결과 동작 | ↩ 열기 · ⌘↩ Finder에서 보기 · ⌘C 경로 복사 |
| 패널 | Esc 즉시 닫기. 다시 열면 이전 검색어 전체 선택. ⌘C 뒤 닫고 이전 앱으로 복귀 |
| 단축키 | ⌃⇧F (`defaultHotkey(key: "f")` → dev는 ⌃⌥⇧F) |
| 인덱싱 시작 | 앱 시작 5초 뒤 자동, `.background` QoS. 설정에서 끌 수 있음 |

### 핵심 동작

- **메모리**: 110만 항목에 약 45~55MB(목표 60MB 이하). 검색과 쓰기가 겹쳐 복사가 일어나면 최대 약 110MB.
- **동시성 (Swift 6)**
  - actor `FileIndexer`가 인덱스 값을 소유합니다. 검색은 `snapshot()` 값을 액터 밖에서 `nonisolated` 병렬로 처리합니다. 키를 칠 때마다 이전 Task를 `cancel()`합니다.
  - 파일 I/O(스캔, 디렉터리 읽기)는 액터 밖 큐에서 합니다.
  - `@unchecked Sendable`은 FSEvents 콜백 박스와 `NSRegularExpression` 래퍼 두 곳에서만 씁니다.
- **FSEvents**
  - 플래그: `FileEvents | WatchRoot | IgnoreSelf | UseCFTypes`, 지연 1.0초. 제외 경로는 `FSEventStreamSetExclusionPaths`로 넘깁니다(최대 8개).
  - 생성·삭제·이름 변경 이벤트는 **부모 디렉터리 dirty 집합**으로 모은 뒤 `DirectoryReconciler`로 실제 목록과 비교합니다. 그래서 이벤트가 합쳐지거나, 대소문자만 바뀌거나, NFD여도 안전합니다.
  - 수정만 있는 이벤트는 무시합니다.
  - `MustScanSubDirs`는 하위 트리를 다시 스캔합니다. `RootChanged`, `EventIdsWrapped`, 장치 UUID 변경은 전체를 다시 스캔합니다.
- **영속화**
  - 위치: `~/Library/Caches/<bundleId>/FileIndex/index.v1`, 권한 0600
  - 저장 시점: 전체 스캔 후, HistoryDone 때 바뀐 게 있으면, `applicationWillTerminate`(새로 추가), 바뀐 상태로 1시간이 지나면. 저장 전에 compact하고 원자적으로 rename합니다.
  - 시작할 때: 스냅샷 로드 → `sinceWhen = lastEventId`로 기록 재생. 설정 해시나 UUID가 다르면 전체 재스캔합니다.
- **TCC**
  - 첫 스캔 때 안내 토스트를 한 번 띄웁니다.
  - Desktop/Documents/Downloads/iCloud Drive가 거부되면 설정에 경고를 표시합니다. 설정 창이나 패널을 열 때 `opendir`로 다시 시도합니다.
  - ~/Library 보호 폴더는 조용히 건너뜁니다.
- **쿼리**
  - ASCII 질의는 바이트 빠른 경로로 처리합니다.
  - 호환 자모 자음(ㄱ~ㅎ 19개)은 같은 자모이거나 그 초성을 가진 음절과 일치합니다(`ㅎㄱ` → 한글).
  - 경로항은 부모가 먼저 나오는 순서를 이용해 순차 패스 한 번으로 "경로 포함" 비트셋을 만듭니다.
  - 정렬 키: 점수 내림차순 → 이름 길이 → 깊이 → 경로 사전순.
- **패널**
  - `[.borderless, .nonactivatingPanel]`, `level .floating`, `NSVisualEffectView`, 폭 680pt, 커서 화면에서 위쪽 모서리 고정.
  - 결과는 view 기반 **NSTableView**(`refusesFirstResponder`)입니다.
  - Enter·Esc·↑↓는 `control(_:textView:doCommandBy:)`에서 처리합니다. 그래서 IME 조합을 확정하는 Enter는 파일을 열지 않습니다.
  - 기본은 `NSApp.activate()` + `makeKey`(검증된 경로)입니다. ④단계 스파이크에서 activate 없이도 IME가 되면 그쪽을 고릅니다.
  - 상태 줄: 인덱스 개수·진행 상황, 일치 수와 시간, 정규식 오류, 키 힌트.

### 앱 연동 (컬러 피커 커밋 8122f5f 패턴)

- **`HotKeyCenter.Action`**: `case findFile = 6`(제목 "파일 찾기")을 추가합니다. 설정의 단축키 행은 자동으로 생깁니다.
- **`Preferences`** 키
  - `hotkeyFindFile`
  - `findFileEnabled`(true)
  - `findFileRoots`(`["~", "/Applications", "/System/Applications"]`)
  - `findFileExclusions`(줄 단위 String)
  - `findFileIncludeHidden`(false)
- **`AppDelegate`**
  - `lazy var findFile`, `onAction`, `@objc findFile(_:)`
  - 시작할 때 `startIndexingIfEnabled()`, `applicationWillTerminate`에서 저장
  - URL `find?q=`: 패널만 열고 결과는 자동으로 열지 않음
  - DEBUG 라우트: `debug/find-stats?path=`, `debug/find-query?q=&path=`, `debug/find-rebuild`
- **메뉴**: `StatusItemController`의 Actions와 hotkeyItems(구분선으로 나눔), `MenuSupport` 파일 메뉴에 항목 추가.
- **설정 섹션**: 사용 토글, 검색 폴더(+/−), 제외 규칙(TextEditor + 기본값), 숨김 토글, 인덱스 상태와 "다시 만들기", 전체 디스크 접근 상태와 "시스템 설정 열기". 값이 바뀌면 2초 디바운스 후 `reconfigure`합니다. 창 높이를 넘으면 `DisclosureGroup("고급")`으로 접습니다.

## 검증

- **단위 테스트**(swift-testing, 약 70개 추가)
  - 초성(`ㅎㄱ` → 한글.txt, `ㅎㄱ` ↛ 하늘), 조합 중 음절
  - 등급 순서, 경계 보너스, 경로항(`proj/src`, `~/Doc`), `ext`/`folder`/`regex`
  - 스냅샷 왕복과 손상 거부, 압축 후 경로 동일
  - 재조정 멱등
- **성능**
  - `log stream --predicate 'subsystem == "com.motolies.mcapture.dev" AND category == "findfile"'`
  - `footprint -p mCaptureDev`
  - 목표: 쿼리 p95 50ms 이하, 스냅샷 로드 300ms 이하, 첫 스캔 30초 이하, 상주 메모리 60MB 이하
- **dev 앱 실제 조작**(메모리 규칙: 항상 dev 앱으로, 끝나면 `pkill -x mCaptureDev`)
  1. `defaults export com.motolies.mcapture`로 사용 중인 앱의 설정을 미리 저장합니다.
  2. `./scripts/build-app.sh`로 빌드한 뒤 `findFileRoots`를 scratchpad 시험 폴더로 바꿉니다.
  3. `open "mcapture-dev://debug/find-rebuild"` → `debug/find-query?q=ㅎㄱ&path=…json`으로 결과 JSON을 확인합니다.
  4. `mv`/`rm` 후 약 2초 뒤 다시 질의해 FSEvents 반영을 확인합니다.
  5. `pkill` → 파일 변경 → 재실행해 기록 재생을 확인합니다.
  6. `mcapture-dev://find?q=main` + `debug/snapshot` PNG로 패널을 확인합니다. 키는 CGEvent `postToPid`로 보냅니다(↓, ↩, ⌘↩, ⌘C, Esc. 앞 앱으로 가져온 뒤, 0.5초 간격). `pbpaste`로 복사된 경로를 확인합니다.
  7. 루트를 기본값으로 돌려 실제 홈 규모의 스캔 시간과 메모리를 기록합니다.
  8. 사용 중인 앱의 설정이 그대로인지 diff로 확인하고, `~/Library/Caches/com.motolies.mcapture/FileIndex`가 생기지 않았는지 봅니다.
- **수동 확인**(스펙 11절에 추가)
  - 두벌식으로 "한글" 입력 중 결과가 계속 갱신되고, 조합을 확정하는 Enter가 파일을 열지 않음
  - 검색 필드에서 ⌘V, ⌘A, ⌘Z가 동작함
  - 전체 화면 앱 위와 여러 디스플레이에서 표시됨
  - TCC 프롬프트, 거부했을 때의 경고, 허용 후 다시 시도
  - 설정 변경 → 재스캔, 인덱스 끄기 → 메모리 해제와 스냅샷 삭제
